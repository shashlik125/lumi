## 1. Общие сведения

Веб-приложение **Lumi** представляет собой клиент-серверную информационную систему, предназначенную для мониторинга, анализа и визуализации эмоционального состояния пользователя. Доступ к системе осуществляется через веб-браузер без установки дополнительного программного обеспечения.

**Ключевые возможности программы:**
- Ведение дневника настроения с привязкой ко времени
- Визуализация эмоциональной динамики (календарь, графики, диаграммы)
- Аналитическая обработка пользовательских данных
- Интеграция календаря менструального цикла
- Чат-ассистент для эмоциональной поддержки

## 2. Функциональное назначение

Программа реализует следующий набор функций:

| № | Функция | Описание |
|---|---------|----------|
| 1 | Регистрация и аутентификация | Создание учётной записи по email и паролю, вход в систему |
| 2 | Дневник настроения | CRUD-операции с записями: оценка (1-10), дата, время, текстовая заметка |
| 3 | Интерактивный календарь | Цветовая индикация дней на основе средней оценки настроения |
| 4 | Аналитический модуль | Построение круговых, столбчатых и линейных диаграмм, расчёт средней оценки и количества «хороших» дней |
| 5 | Календарь цикла | Отслеживание менструального цикла с фиксацией симптомов |
| 6 | Цели и радости | Ведение списка целей с отметкой выполнения и фиксация положительных событий |
| 7 | Чат-ассистент «Ася» | Анализ записей пользователя, формирование отчётов, ответ на текстовые команды |
| 8 | Экспорт данных | Выгрузка записей настроения, целей и положительных событий в формате CSV |

## 3. Описание логической структуры

### 3.1 Архитектура программы

Программа построена на основе **трёхуровневой архитектуры**, что обеспечивает разделение ответственности между компонентами и упрощает сопровождение кода.

**Уровень 1 — Клиентский (Frontend)**
- **Технологии:** HTML5, CSS3, JavaScript (ES6), Chart.js, Font Awesome
- **Назначение:** отображение пользовательского интерфейса, обработка действий пользователя, визуализация графиков и диаграмм, асинхронное взаимодействие с сервером через REST API.

**Уровень 2 — Серверный (Backend)**
- **Технологии:** Python 3.11, Flask, Flask-Login, Flask-Bcrypt, SQLAlchemy
- **Назначение:** реализация бизнес-логики, обработка HTTP-запросов, аутентификация и управление сессиями, валидация данных, взаимодействие с базой данных.

**Уровень 3 — Хранения данных (Database)**
- **Технологии:** PostgreSQL 15+
- **Назначение:** централизованное хранение всех пользовательских данных, обеспечение целостности и согласованности информации.

### 3.2 Структура базы данных

Логическая модель базы данных включает следующие основные сущности:

| Сущность | Назначение | Связь с users |
|----------|------------|:-------------:|
| `users` | Учётные записи пользователей (email, хеш пароля, имя, пол, дата рождения, аватар) | — |
| `mood_entries` | Записи настроения (оценка 1-10, дата, время, текстовая заметка) | 1 : N |
| `hourly_moods` | Почасовые записи настроения для детализации в течение дня | 1 : N |
| `cycle_entries` | Дни менструального цикла (день цикла, симптомы, интенсивность) | 1 : N |
| `cycle_settings` | Настройки цикла пользователя (длительность, средняя продолжительность) | 1 : 1 |
| `goals` | Цели пользователя (текст цели, статус выполнения, дата создания) | 1 : N |
| `joys` | Положительные события (текст события, дата) | 1 : N |

**ER-связи:** Все перечисленные сущности, за исключением `cycle_settings` (связь 1:1), связаны с таблицей `users` отношением «один ко многим» (1:N).

### 3.3 Взаимодействие модулей

Взаимодействие компонентов системы осуществляется по следующей схеме:

1. Пользователь через браузер инициирует действие (например, добавление записи настроения).
2. Клиентская часть формирует HTTP-запрос (GET, POST, PUT, DELETE) к соответствующему эндпоинту REST API сервера.
3. Серверная часть (Flask) принимает запрос, выполняет аутентификацию (при необходимости), валидирует входные данные и вызывает соответствующий обработчик.
4. При необходимости сервер выполняет CRUD-операции с базой данных PostgreSQL через ORM SQLAlchemy.
5. Результат обработки (данные или статус операции) возвращается клиенту в формате JSON.
6. Клиентская часть динамически обновляет интерфейс без перезагрузки страницы.

**Особые сценарии:**
- **Чат-ассистент «Ася»** обрабатывает текстовые команды, анализирует записи пользователя из базы данных и формирует текстовый ответ.
- **Экспорт данных** генерирует CSV-файл на сервере и возвращает его клиенту для скачивания.
- **Календарь настроения** рассчитывает среднюю оценку за день и определяет цвет индикации на стороне сервера при загрузке данных.

## 4. Используемые технические средства

### Требования к серверной части (хостинг / деплой)

| Компонент | Минимальные требования |

| Компонент | Требование |
|-----------|-------------|
| Браузер | Google Chrome 90+, Mozilla Firefox 88+, Microsoft Edge 90+, Safari 14+ |
| Подключение к интернету | Стабильное, скорость от 1 Мбит/с |

## 5. Вызов и загрузка

### 5.1 Точка входа

Главный файл запуска: **`run.py`** (корень репозитория)

### 5.2 Локальный запуск (режим разработки)

| Шаг | Команда / Действие |
|-----|---------------------|
| 1 | `git clone https://github.com/shashlik125/lumi.git` |
| 2 | `cd lumi` |
| 3 | `python -m venv venv` |
| 4 | `source venv/bin/activate` (Linux/macOS) или `venv\Scripts\activate` (Windows) |
| 5 | `pip install -r requirements.txt` |
| 6 | Создать файл `.env` с переменными: `DATABASE_URL`, `SECRET_KEY` |
| 7 | `python run.py` |

**После запуска:** сервер доступен по адресу `http://localhost:5000`

### 5.3 Продуктивная среда (деплой)

| Параметр | Значение |
|----------|----------|
| Платформа | Railway.app |
| Автоматизация | При пуше в ветку `main` на GitHub |
| База данных | Управляемый PostgreSQL (через Railway) |
| Переменные окружения | Настраиваются в панели Railway (`DATABASE_URL`, `SECRET_KEY` и др.) |
| Адрес сервера | Предоставляется Railway при каждом деплое |

## 6. Входные и выходные данные

### 6.1 Входные данные

| Тип данных | Формат | Пример | Обязательность |
|------------|--------|--------|:--------------:|
| Регистрационные данные | email, пароль (мин. 8 символов) | `user@example.com`, `password123` | Да |
| Запись настроения | оценка (1-10), дата (YYYY-MM-DD), время (HH:MM), заметка (текст) | `8`, `2026-06-09`, `14:30`, «Хороший день» | Оценка, дата, время — да; заметка — нет |
| Параметры цикла | день цикла, симптомы, интенсивность | `1`, «головная боль», `3` | Да (при использовании модуля) |
| Сообщение чат-ассистенту | текст (до 1000 символов) | «проанализируй моё настроение» | Да (при отправке) |
| Цель | текст цели | «Кататься на велосипеде» | Да |
| Положительное событие | текст события | «Вкусно поела» | Да |
| Аватар пользователя | PNG, JPG, JPEG | `avatar.png` | Нет |

### 6.2 Выходные данные

| Тип данных | Формат | Назначение |
|------------|--------|-------------|
| Цветовая индикация календаря | CSS-цвет (зелёный / розовый / красный / серый) | Визуальная оценка динамики настроения |
| Графики и диаграммы | HTML5 Canvas (Chart.js) | Визуализация распределения и динамики настроения |
| Статистические показатели | Числовые значения | Количество «хороших» дней, средний балл |
| Ответы чат-ассистента | Текстовая строка | Анализ данных, рекомендации, поддержка |
| CSV-файл экспорта | CSV (UTF-8, запятая) | Выгрузка записей, целей и радостей |
| Сообщения об ошибках | Текст (всплывающее уведомление) | Информирование об ошибках |

### 6.3 Формат CSV-экспорта (пример)

## 7. Особенности реализации

### 7.1 Обеспечение безопасности

| Мера защиты | Реализация |
|-------------|------------|
| Хеширование паролей | Flask-Bcrypt (bcrypt), хранение только хеша |
| Управление сессиями | Flask-Login, защищённые cookies |
| Защита от SQL-инъекций | Параметризованные запросы через SQLAlchemy |
| Защита от XSS-атак | Экранирование пользовательского ввода |
| Шифрование передачи данных | HTTPS (Railway.app) |
| Конфиденциальность | Переменные окружения для ключей и паролей |
| Контроль доступа | Только после успешной аутентификации |

### 7.2 Масштабируемость и сопровождение

| Характеристика | Описание |
|----------------|----------|
| Слабая связанность | Трёхуровневая архитектура позволяет независимо изменять компоненты |
| Горизонтальное масштабирование | Серверная часть stateless → несколько экземпляров за балансировщиком |
| Версионирование кода | Git / GitHub |
| Автоматизация деплоя | Автоматическое развёртывание на Railway.app при пуше в `main` |

### 7.3 Ограничения программы

| Ограничение | Описание |
|-------------|----------|
| Интернет | Требуется стабильное подключение |
| Медицинское использование | Программа **не является** медицинским изделием |
| Чат-ассистент | Не даёт медицинских и психотерапевтических рекомендаций |
| Длина заметки | Максимум 500 символов |
